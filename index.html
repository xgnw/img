本地模式用来试界面和流程，复制出来的链接只在这台浏览器里能打开。填好仓库和令牌、测试通过后再切到 GitHub。
写 owner/repo，例如 yourname/images。公开仓库图片谁都能看，私有仓库只有带令牌的请求能读到。
往哪个分支写图，一般填 main。jsDelivr 的外链会带上这个分支名。
新文件写到 img/2026/11/8f3a1c.webp 这类路径，按年月分开，列表只扫这个目录。
Fine-grained 令牌，只勾这个仓库的 Contents: Read and write。存在本机 localStorage，不往别处发。
三个域名指向同一份文件，只影响直链前缀。页内预览会自动换域名重试，某个域名被网络掐断也能显示。

不需要服务器，也不需要 Worker。浏览器直接用 GitHub 的 Contents API 把图片提交进仓库，再用 jsDelivr 或 raw 链接把图片发出去。

建一个公开仓库

New repository，勾上 Public，并且勾选 Add a README file 让它产生第一次提交——空仓库没有 main 分支，第一次写入会失败。仓库名例如 images。

建一个只写这个仓库的令牌

Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token。Repository access 选 Only select repositories 指向刚建的仓库，Permissions 里把 Contents 设为 Read and write，其余留空。

填进设置页

仓库填 owner/repo，分支 main，目录 img，粘上以 github_pat_ 开头的令牌。点「测试仓库」，看到「已连接」再切到 GitHub 模式。

开始用

入库页拖图或粘贴截图，上传完直接复制直链。形如 https://cdn.jsdelivr.net/gh/owner/repo@main/img/2026/11/8f3a1c.webp，贴到哪里都能显示。

页面和图片可以放同一个仓库。把这份 index.html 提交到仓库根目录，图片目录仍填 img，图库只会扫这个目录，不会把页面自己列进去。想给控制台一个固定网址，就在仓库 Settings → Pages 里选 Deploy from a branch、分支 main、目录 /root，之后用 https://owner.github.io/repo/ 打开——这个地址是 https，剪贴板和粘贴上传都比本地文件更顺。
仓库必须是公开的。jsDelivr 只读公开仓库；私有仓库的 raw 链接要带上令牌才能访问，发出去别人打不开。图片里有隐私内容，就别用这套方案。
几个会碰到的限制：走 Contents API 单文件建议控制在 10 MB 以内（本页上限 25 MB，大文件要先转 Base64，慢且容易超时）；GitHub 建议仓库体积不超过 1 GB；带令牌的请求每小时 5000 次，正常上传根本用不完。
jsDelivr 的缓存：同一链接会被 CDN 缓存，覆盖写同名文件后旧图可能还挂着。这套方案每次都用随机文件名，不覆盖写，所以不会碰到这个问题；真要强制刷新，可以在链接后加 ?v=时间戳。
